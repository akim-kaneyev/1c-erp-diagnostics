# Support

## Usage questions and reproducible bugs

Use GitHub Issues after confirming that the problem is not already documented.

Before opening an issue:

1. remove all customer/company identifiers and secrets;
2. do not attach production `.dt`, backups or credentials;
3. reduce the case to the smallest reproducible sanitized example;
4. include the plugin/project version and relevant Gate 1–10 status;
5. state what result you expected and what actually happened.

## Security reports

Do not disclose vulnerabilities, credentials or confidential case data in a public issue. Use GitHub private vulnerability reporting when it is enabled for the public repository. If that channel is unavailable, open a minimal public issue requesting a private contact without including sensitive details.

## Scope

The project provides diagnostic workflows and tools. It does not guarantee accounting correctness without sufficient case evidence and does not replace qualified review of production changes.
