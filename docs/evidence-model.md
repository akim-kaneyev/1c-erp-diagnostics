# Evidence model

## Факт
Непосредственно следует из предоставленного материала.

## Интерпретация
Объяснение значения факта. Должна быть привязана к полям выгрузки или документации.

## Гипотеза
Предполагаемая причина.

## Статус утверждения оценивается отдельно

Статус назначается каждому claim, а не всему пакету доказательств одним значением.

Например, по производной таблице без lineage одновременно допустимы два разных вывода:

- `УСТАНОВЛЕНО`: в предоставленном описании/артефакте отсутствуют заявленные `derived_from`, transformation, run/output identifiers;
- `ТРЕБУЕТ ПРОВЕРКИ`: значение присутствовало в исходном файле, производная таблица получена именно из него, либо это различие стало причиной симптома.

Доказанная ограниченность доказательства не является доказанной первопричиной. И наоборот, отсутствие доказанной причины не требует понижать непосредственно наблюдаемый факт до гипотезы.

## Доказанная причинная связь
Нужны исходный симптом, конкретное отличие, механизм использования этого отличия, наблюдаемый результат, проверка альтернатив и желательно контролируемое сравнение до/после.

## Artifact anchor и derivation lineage

Каждый существенный факт или производный артефакт должен иметь прослеживаемое происхождение до исходного материала.

Для исходного Evidence ID фиксируй источник и стабильный идентификатор/хэш, когда он доступен. Для производного Evidence ID дополнительно фиксируй:

- `derived_from` — один или несколько родительских Evidence ID;
- `transformation` — что именно было сделано: extraction, normalization, filter, join, comparison, parser/export или иная операция;
- `tool/version` — инструмент и версия/commit/ref, если операция выполнялась инструментом;
- `run_id` — идентификатор конкретного выполнения, если derivation создавалась исполняемым шагом;
- `output_hash` — хэш производного результата, когда материал сохраняется или может быть стабильно сериализован.

Производный артефакт без родительского anchor не может единолично подтверждать исходное содержимое или первопричину. Если происхождение существенного промежуточного результата не восстанавливается, causal/provenance closure для зависимого вывода считается разорванной.

## Execution identity

Результат внешнего инструмента, sandbox, parser, static analyzer или автоматизации допустим как исполняемое доказательство только если можно установить, к какому запуску и входам он относится. Минимальный execution record:

- `run_id`;
- `case_id`;
- `input_hashes` или стабильные идентификаторы входов;
- release платформы/конфигурации, extension set и учетный period;
- `tool` и `tool_version/ref`;
- точная `operation`;
- `started_at` и `completed_at`, когда доступны;
- `output_hash` или стабильный output identifier;
- ограничения/ошибки выполнения.

Результат от другого `case_id`, от несовпадающих входов, release/extensions/period или от предыдущего запуска после изменения входных данных является stale evidence и не может подтверждать текущий вывод до повторного выполнения или доказанного эквивалентного соответствия. Движение, временная таблица, отчет и post-change result образуют одну цепочку только при совместимой execution identity; имя файла, номер или одинаковая сумма недостаточны.

## Accounting invariant Evidence

Для распределения, себестоимости, закрытия, остатков, проводок и долевых алгоритмов машинный raw-row результат является отдельным derived Evidence. Он хранит input hash, expected row IDs, coverage, явные исключения с Evidence IDs, суммы/количества, per-analytic reconciliation, exact shares, observed allocation + residual и formula trace с row IDs.

Before/after classification сохраняет пять флагов эффекта. Эти поля не расширяют закрытую top-level schema `EVAL_RESULT_JSON`; в strict result попадают только Evidence/Claim ссылки и допустимые поля skeleton.

## Machine state integrity

`STATE.json` обеспечивает глобальную уникальность Evidence/Run/Claim/Document IDs, ссылочную целостность, отдельные dependency/temporal графы и invalidation closure. Stale/superseded/withdrawn источник распространяется через run, derived Evidence, Claim, report/document и первый затронутый downstream Gate. Markdown-журнал не может переопределить машинный active index.

## Provenance closure

Предварительное или финальное root-cause `УСТАНОВЛЕНО` требует замкнутой доказательной трассы:

`source artifact → inspected/derived evidence → claim premises → causal links → conclusion`.

Каждый существенный переход должен иметь artifact anchor, derivation lineage или прямую ссылку на исходное доказательство. Нельзя закрывать пробел ссылкой на уверенность модели, типичное поведение ERP, чистый build/static check или итоговый отчёт инструмента без трассы к его входам.

## Scope closure

Завершение текущей задачи и разрешение связанного инцидента оцениваются отдельно.

- Текущая задача «оценить достаточность доказательств» может быть закрыта после корректного вывода `EVIDENCE_REQUIRED`.
- Связанный вопрос о фактическом содержимом источника или первопричине при этом остаётся `blocked` или `open`.
- `not_in_scope` используется только при явном исключении связанного инцидента из запроса.

## Synthetic capability snapshot

В машинных eval-кейсах capability snapshot является частью входных данных. Результат должен повторять только заявленные имена и статусы. Внутренние шаги рассуждения, packaged skills, synthesis/review роли и придуманные названия операций не являются runtime capabilities. Пустой snapshot означает `capabilities: []`.

## Неприемлемые переходы
- «есть ошибка закрытия» → «причина в регистре X»;
- «после перепроведения стало хорошо» → «документ был поврежден»;
- «в типовой ERP обычно используется объект X» → «в этом кейсе причиной был X»;
- «парсер/анализатор выдал результат Y» → «Y относится к текущим входам» без execution identity;
- «производная таблица содержит значение» → «значение было в исходном файле» без derivation lineage;
- «все отдельные ссылки присутствуют» → root-cause `УСТАНОВЛЕНО`, если между ними остаётся недоказанный причинный переход;
- «доказательств причины недостаточно» → «не установлено даже отсутствие lineage», если отсутствие lineage прямо задано материалом;
- «внутренне выполнен анализ» → «доступна отдельная runtime capability».
