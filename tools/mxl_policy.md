# MXL policy

В репозитории нет выдуманного универсального MXL-парсера.

Без подтвержденного формата конкретного `.mxl` безопасный порядок:
1. Сохранить исходный MXL неизменным вне Git.
2. В 1С экспортировать тот же табличный документ в XLSX, PDF, HTML, XML или TXT/CSV, если структура не теряется.
3. Для структурного анализа приоритет XLSX/XML.
4. Для визуальной проверки — PDF.
5. Зафиксировать связь экспорта с исходным MXL.
6. Зафиксировать `rows_present`, число строк/колонок, preview заголовков, preview значений и hash экспорта.
7. Если видны только property tree/schema/column metadata без значений, классифицировать результат как `wrong_view/incomplete`; Gate 2 по содержимому строк не проходит.
8. Повторять экспорт только после изменения инструкции и нового визуального gate, подтверждающего правильный вид.

Для XLSX-экспорта `tools/xlsx_profile.py` детерминированно фиксирует hash, физическое наличие табличных строк, `row_count`, `column_count`, редактированные header/value previews и `view_status`. Автоматически отличить property tree от строк бизнеса по количеству ячеек нельзя: `rows_present=true` допускается только с `--view-kind rows`, `--view-sheet-index N` и Evidence ID нового визуального gate, относящегося именно к листу `N`. Один visual-gate Evidence ID не подтверждает другие листы книги. `--view-kind property_tree` всегда дает `wrong_view/incomplete`. Credential-like и абсолютные пользовательские значения в preview редактируются и дают `FAIL`. Связь с исходным MXL всё равно должна быть зафиксирована отдельно.

Конкретный MXL-конвертер добавляется только после проверки и с тестами.
