# Diagnostic viewer

Follow the installed ui-sdk skill. Before using components, read node_modules/@ui-sdk/react/docs/llms.txt and the relevant component pages. Use UI SDK parts for every interactive control. Keep original case data immutable, preserve exact statuses and treat filtering, file-hash verification and accounting validation as distinct operations.

The file viewer remains local and read-only: opening a file must never transmit it or start a database connection. The explicitly requested workbench is a separate screen backed by the opt-in loopback server. It may connect only to an explicitly selected test profile and collect allowlisted reads after sign-in. No posting, arbitrary BSL or database write action belongs in either screen. Case files and notes are private local workspace artifacts; do not change the original evidence or automatically accept an accounting conclusion. Test actual state after human and agent actions, including rejected changes, empty results and dialog focus recovery.
